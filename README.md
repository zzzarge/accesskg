# AccessKG

Карта и маршруты по Бишкеку для людей на колясках, родителей с детскими колясками и пожилых людей. Навигатор говорит, что путь есть. AccessKG показывает, кто и когда проверил, что по нему можно проехать.

Команда **Vital Bros**.

## Что умеет

- **Два маршрута сразу**: кратчайший пеший и доступный для выбранного профиля, с разницей в метрах.
- **Профили мобильности**: ручная коляска, электроколяска, детская коляска, ходунки. У каждого свои пределы по бордюру, уклону и ширине прохода.
- **Точки на карте**: съезды, пандусы, высокие бордюры, ступени, крутые уклоны, разбитое покрытие, узкие проходы, временные препятствия. С фото.
- **Индекс доверия** у каждой точки: источник + подтверждения + свежесть проверки.
- **Голоса** «Всё ещё так» / «Уже не актуально». Две отметки «не актуально» убирают точку с карты.
- **Временные препятствия исчезают сами**: машина на тротуаре через 4 часа, раскопки через 7 дней.
- **Паспорт входа** у важных мест: ступени, пандус, дверь, кнопка вызова, туалет.
- **Для мэрии**: рейтинг барьеров по тому, сколько школ, поликлиник, аптек и остановок рядом, и выгрузка в CSV.
- **Режим команды**: по командному коду точки помечаются «Проверено командой на месте», и можно добавлять важные места.
- **Работает на телефоне** и ставится как приложение (PWA). Новые точки от других людей появляются сразу.

Без настроек приложение запускается в **демо-режиме** на встроенных данных.

## Запуск за 20 минут

Понадобятся три бесплатных аккаунта: Supabase (база), OpenRouteService (маршруты), Vercel (хостинг).

### 1. База данных: Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (регион — ближайший, например Frankfurt).
2. Откройте **SQL Editor**, вставьте целиком файл `supabase/schema.sql`, нажмите **Run**.
3. По желанию: так же выполните `supabase/demo_seed.sql`, чтобы на карте были демо-точки для показа.
4. Откройте **Project Settings → API** и скопируйте:
   - **Project URL** и ключ **anon public** → в файл `js/config.js`;
   - ключ **service_role** → понадобится в шаге 3. Никогда не кладите его в код и не показывайте никому.

```js
// js/config.js
SUPABASE_URL: 'https://ВАШ-ПРОЕКТ.supabase.co',
SUPABASE_ANON_KEY: 'eyJ...',
```

### 2. Маршруты: OpenRouteService

1. Зарегистрируйтесь на [openrouteservice.org](https://openrouteservice.org/dev/#/signup).
2. В личном кабинете создайте ключ (**Request a token**, тип Standard). Бесплатно — около 2000 маршрутов в день.

### 3. Хостинг: Vercel

1. Зарегистрируйтесь на [vercel.com](https://vercel.com) через GitHub.
2. **Add New → Project** → выберите репозиторий `accesskg` → Framework: **Other**, ничего не собирать.
3. В **Environment Variables** добавьте:

| Переменная | Значение |
| --- | --- |
| `ORS_API_KEY` | ключ OpenRouteService |
| `SUPABASE_URL` | Project URL из Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | ключ service_role из Supabase |
| `TEAM_CODE` | командный код **не короче 16 символов**, например `vital-bros-чай-самса-2026` |

4. **Deploy**. Через минуту приложение будет по адресу вида `accesskg.vercel.app`.

Каждый `git push` в `main` автоматически обновляет сайт.

### Проверка

- Откройте сайт → бейдж «Демо-режим» исчез → значит, Supabase подключён.
- Выберите A и B → появились два маршрута → значит, ORS работает.
- Вкладка «Добавить» → «Я из команды» → введите `TEAM_CODE` → появился бейдж «Команда».

## Как собирать данные в поле

1. Выберите **один маршрут-коридор на 3–5 км**: например, от остановки до поликлиники и школы. Лучше проверить его идеально, чем весь район наспех.
2. Войдите в режим команды. Идите по маршруту и на каждом переходе, входе и проблемном месте нажимайте «Добавить» → «Я здесь» → тип → фото → «Сохранить».
3. **Бордюр** измеряйте рулеткой в сантиметрах. **Уклон** — приложением-уровнем на телефоне, в процентах (5° ≈ 9%).
4. Сначала добавьте **важные места** (школа, поликлиника, аптека, остановка) и заполните паспорт входа: по ним считается рейтинг для мэрии.
5. Пройдите маршрут с человеком на коляске и запишите его отзыв — это лучший слайд для жюри.
6. Перед показом удалите демо-данные в SQL Editor:

```sql
delete from public.points where is_demo;
delete from public.places where is_demo;
```

## Локальный запуск

Без маршрутов (только карта и данные) — любой статический сервер:

```bash
python3 -m http.server 8000   # затем http://localhost:8000
```

С маршрутами — через Vercel CLI, он поднимает и функции из `/api`:

```bash
npm i -g vercel
vercel link          # один раз
vercel env pull      # скачает переменные окружения
vercel dev           # http://localhost:3000
```

Тесты логики и серверных функций (нужен Node 18+, без установки пакетов):

```bash
npm test
```

```
js/data.js            Supabase или демо-режим
js/routing.js         запросы маршрутов к /api/route
js/lib/profiles.js    профили мобильности и их пределы
js/lib/barriers.js    типы точек; правило «проходит ли профиль»
js/lib/trust.js       индекс доверия
js/lib/ranking.js     рейтинг для мэрии и CSV
js/lib/geo.js         расстояния и зоны обхода
api/route.js          сервер: маршрут через OpenRouteService (ключ скрыт)
api/team.js           сервер: точки команды и важные места (по командному коду)
supabase/schema.sql   таблицы, правила доступа, хранилище фото
sw.js, manifest       установка на телефон (PWA)
tests/                тесты: npm test
```

### Как устроены маршруты

1. Пеший маршрут строится через OpenRouteService как есть — это «кратчайший».
2. Доступный: профиль `wheelchair` в ORS с пределами уклона и бордюра плюс **зоны обхода** — маленькие квадраты вокруг каждой точки из нашей базы, которая непроходима для выбранного профиля.
3. Если в OpenStreetMap мало данных о тротуарах и ORS не находит путь для коляски, приложение строит пеший путь в обход наших барьеров и честно об этом пишет.
4. Потом приложение проверяет, какие наши точки лежат в 12 м от каждой линии: барьеры на кратчайшем пути и «доказательства» на доступном.

## Доработка с ИИ

Код без сборщика и зависимостей, поэтому его удобно дорабатывать с Claude или в Claude Code: откройте репозиторий и опишите, что нужно, например «добавь поиск адреса через ORS geocode в /api» или «добавь зимний слой: точки типа snow, которые исчезают через 2 дня».

Идеи из плана развития:

- зимний слой: снег и лёд на тротуарах;
- автосбор: GPS-трек поездки подтверждает проходимость участка;
- выгрузка проверенных данных в OpenStreetMap (теги `wheelchair`, `kerb`, `incline`);
- вход для команды через Supabase Auth вместо общего кода.

## Ограничения

- Командный код общий на всю команду. Для настоящего запуска замените его на вход через Supabase Auth.
- Один голос с устройства за точку проверяет база, но устройство определяется по случайному ID в браузере, и упорный человек может его подменить. Поэтому точку команды убирают только 4 голоса «не актуально». Для настоящего запуска — вход через Supabase Auth.
- Рейтинг для мэрии — оценка охвата (сколько важных мест рядом с барьером), а не точный расчёт объездов.
- Тайлы карты берутся с серверов OpenStreetMap; для большой нагрузки нужен свой провайдер тайлов.
